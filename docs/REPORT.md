# InfiniteBench 数据体检与基线报告

> 2026-11-18　|　12 个任务 / 560 条模型预测　|　模型 gpt-6-sol　|　截断预算 100k token

## 0. 摘要

1. **12 个子任务里有 4 个零模型可解**：PassKey / Number / KV / Math.Find 的正则基线全是 100%。这些任务的分数反映“能不能定位字符串”，不是长上下文理解。
2. **模型总体答对 76.1%**（426/560），但格式失败只剩 0.2%——修 prompt 前是 11.2%。
3. **在四个检索类任务上，模型仍低于三行正则**（88–92 vs 100）。
4. **En.Sum 的 ROUGE 失效**：20 条人工评均分 4.6/5，ROUGE 只有 11.3，秩相关 −0.05，指标测不出内容对错。
5. **真正属于模型能力问题的失败只有 29 条（5.2%）**，其余来自指标、提示词、输出形态。

## 1. 数据集概况

InfiniteBench 共 12 个子任务、3946 条样本、约 2.33 GB。这 12 个任务并不独立：70 段上下文跨任务复用，涉及 582 条（14.7%）。

## 2. 方法

```
① 对齐口径（读官方判分代码） → ② 体检 → ③ 建 chance level
   → ④ 零模型可解性 → ⑤ 问题分诊
```

三处口径必须按代码来，README 没写：

1. 选择题的 `answer` 只有选项文本，判分器要 `[文本, 字母]`，必须先补字母；
2. Math.Calc 是“最长正确前缀比例”，不是全对才算对；
3. 官方对 gpt4 有 `pred_nums[1:]` 特判——同一模型换个名字，分数会变。

## 6. 讨论

### 6.1 为什么“跑不满”

按顺序排查，四个原因的重要度递减：

1. **指标不适用**（最大）：En.Sum 20 条人工评 4.6/5，ROUGE 11.3，秩相关 −0.05。这不是模型问题，是 ROUGE 只奖励措辞重合。
2. **提示词缺信息**：v1 没把 options 送进 prompt，选择题必然 0 分。修完后 +90。
3. **输出形态**：Code.Run 的数字位置、Math.Calc 的长序列，都是“格式”而不是“能力”。
4. **真能力**：检索类任务上模型 88–92 分，正则 100——差距是真的，但只有 8–12 个点。

### 6.2 对使用这份数据的建议

- 报告分数时必须同时给 **chance level** 与**规则基线**；否则不知道分数意味着什么。
- 四个检索类任务不要和长文档任务求平均；它们的难度不在一个维度。
- En.Sum 不要用 ROUGE 排名；要么人工评，要么换语义指标。
- Math.Calc 在 chat API 上不可测（模型不会数完 14999 个数），必须单列。

## 7. 局限

1. **只有一个模型**：中转上没有 Claude，无法做跨厂商对比。
2. **单一 prompt**：v3 只覆盖 zero-shot，few-shot 对照还没跑（表中 planned）。
3. **人工评样本小**：摘要人工评 20 条，只能证明“ROUGE 与内容无关”，不能给精确分数。
4. **长度是估算**：token 数按字符粗估，与官方 tokenizer 有约 1% 偏差。
5. **数据不入仓**：clone 后需自行下载 2.3 GB，见 README。
